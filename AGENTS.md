# Maintenance

Read `skills/README.md` before applying the vendored DSH lifecycle skills. User authorization takes precedence over their generic confirmation templates; do not request approval again for already authorized implementation, tests, GitHub maintenance, pushes, or releases.

Reproduce reported failures before changing production code. Verify the packed artifact through the exact Harness product entry and record the dependency cohort. Do not infer compatibility from a directory name, broad peer range, or a successful typecheck. Keep credentials and raw session logs outside the repository.

Use Ego Lite's `ego-browser` skill for interactive browser work. Reuse the existing `/tmp` Harness workspace during acceptance; do not open a folder picker.

After implementation, use independent adversarial review agents before committing and releasing. Preserve contribution attribution through PR links and original commits where appropriate.
